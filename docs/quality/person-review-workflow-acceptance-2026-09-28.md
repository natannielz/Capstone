## Delivered local boundary

A private selection proof binds the current actor and persistent session, normalized request, database/transaction attempt, durable policy and eligibility heads. Proposal IDs, target groups and account disclosure are conjunctive. Discovery filters complete permitted participants before counts, paging and profile joins; a missing allowed profile produces an explicit repair state. Structural target inspection supports expired/disputed evidence without granting positive authority. Reader permissions, person proofs and session/policy lifetimes are checked through the final awaited audit/read.

Server-held consequence previews capture all affected aliases and their permitted profile versions, the exact target closure, policy, actor epochs and session. The technical maximum is five minutes, capped by current selection/policy/person/permission/membership/MFA/session deadlines. Proposal and approval commands consume the matching ready preview in the same transaction as proposal/history/effects/receipt. A new effect cannot use changed profiles, sources, aliases, policy, actor/session or an expired preview. Final guards run after receipt persistence. A committed exact retry remains recoverable after preview expiry, subject to current command authority, without consuming a second preview or repeating effects.

V10 adds one strict private preview collection and unique reference index. Migration preflights exact types, state, chronology, durable references, original proposal/history relationships, collection/index options and counter high-water marks before DDL. It retains historical previews after ordinary session TTL cleanup; these retained session references are never current authority. No policy, account grant, reviewer appointment or retention rule is seeded.

The private API exposes scoped queue/search/detail, propose/approve previews and commands, reject/withdraw and actor-bound receipt lookup. It uses exact origin, anti-forgery and expected-actor checks, verified server sessions, fresh MFA for sensitive actions, quoted versions and idempotency keys. IDs/counts/revisions remain JSON strings; pagination fields reject quoted numbers. The three existing permission definitions are projected into available navigation/actions; role templates and finance packs are unchanged. Public trust adapters remain unavailable by default.

The Indonesian screen uses named selection, original request/decision, all affected accounts and explicit consequence confirmation. Actor/selection/reason changes invalidate pending previews; stale, denied, inactive service, incomplete profile, offline and uncertain outcomes are distinct. Recovery dispatches person operations to their own validated receipt route, preserves actor/operation/key and keeps only recovery metadata in storage. Exact retry bodies remain in memory. A missing receipt stays unconfirmed; no generic access-resolution or unsafe clear is exposed. After a reload, only retained-reference receipt lookup is available; a future explicit no-effect resolution contract is needed before offering a safe close/replacement action for unresolved requests without an in-memory body.
