# Retired and reclassified tests (Phase E)

Every test that fails on the current candidate gets one of three outcomes:
1. **fixed** — RED→GREEN, with the commit recorded;
2. **rewritten** — it now tests the same guarantee at the current schema;
3. **retired** — marked `Skip = Retired.<Reason>` in code, kept discoverable, and listed here with the test that covers the current path.

A test is retired only when its guarantee cannot apply to any deployable state.

## Retirement reasons

| Reason | Meaning | Why no deployable state is affected | Current path covered by |
| --- | --- | --- | --- |
| `Retired.HistoricalUpgrade` | The test rewinds a fully migrated fixture to the schema it was written against. For example, it asserts `history.Count == 59`, or deletes `schemaMigrations` rows 44–54, and then upgrades. | There is no production database yet (D07 is open). The synthetic local pilot is bootstrapped by migrating an empty database. The first real deployment migrates an empty database to the current version, so no real database can hold these intermediate schemas. Future upgrades start from a released version, and each new migration has its own predecessor test (for example `Migration_118_creates_strict_empty_draft_discard_storage_with_a_thirty_day_window`). | `CollectionMigrations.ApplyAsync` from empty runs in every fixture. Each owner's runtime `RequireStorageAsync` validator and index checks run on every request. The current-version migration test runs per migration. |

## Bulk rewrite: exact schema-version pins

Every `Assert.Equal(N, CollectionMigrations.CurrentVersion)` was a sanity check that the schema was exactly current when the test was written. There were 26 occurrences across `Inventory`, `Procurement` and `Ordering` tests and fixtures, including the shared `OrderStockSourceTestData`, `FulfillmentStockSourceTestData` and `ReconciliationStockSourceTestData`. Each is now `Assert.True(CollectionMigrations.CurrentVersion >= N)`, which asserts that the feature's schema is installed. Tests that still fail after this change are genuine rewinds; the classification run retires them individually with `Retired.HistoricalUpgrade`.
