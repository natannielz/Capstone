# OWASP ASVS 5.0 Level 1 — self-assessment (20 October 2026)

This is a code-reading self-assessment of the current candidate. It is not a penetration test or third-party audit. Each chapter records the verdict, the evidence in the code, and any open gap with its planned fix. Hosted items depend on D07, which is still open: TLS termination, the Auth0 tenant configuration, and secret storage.

| Chapter | Verdict | Evidence | Gap / action |
| --- | --- | --- | --- |
| V1 Encoding and sanitisation | Pass | React escapes all rendered text. Mongo access goes through typed BSON filters, never string-built queries. Documents rendered server-side (invoice, Surat Jalan, receipt proof) are served with `default-src 'none'; sandbox` CSP and `nosniff` (`InvoiceEndpoints.cs`, `ShipmentDocumentEndpoints.cs`). | — |
| V2 Validation and business logic | Pass | Request DTOs refuse unknown members (`JsonUnmappedMemberHandling.Disallow`) and required fields. Domain policies validate bounded text, IDs and decimals. Money is exact decimal (`Money`, canonical decimal strings). Business rules (maker/checker, person evidence, idempotency, version fences) are enforced server-side on every command (`AuthorizationStore.ExecuteCommandAsync`). | — |
| V3 Web frontend security | Pass (since `a92f42c`) | Every route sends CSP (`object-src 'none'`, `base-uri 'self'`, `frame-ancestors 'none'`, same-origin `connect-src`), `nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy` and `Permissions-Policy`, plus HSTS in production (`frontend/src/lib/security-headers.ts`). | CSP keeps `'unsafe-inline'` for scripts (Next "without nonces"). Moving to nonces or SRI is an L2 hardening item. |
| V4 API and web service | Pass | Antiforgery on state-changing requests (`__Host-ut_csrf`, SameSite=Strict). `X-Expected-Actor-Id` binds the request to the signed-in actor. Purpose-bound read DTOs. Private, `no-store` responses for private data. Problem+json errors without stack traces. | — |
| V5 File handling | Pass | Evidence uploads are reserved first, bounded to 10 MB, typed (JPEG/PNG/PDF) and validated server-side. They are stored outside the web root in private evidence storage. Downloads carry `Referrer-Policy: no-referrer` and an exact length. Originals are immutable. | — |
| V6 Authentication | Pass (provider-dependent) | Sign-in is delegated to OIDC (Auth0 adapter) with `__Host-` correlation and nonce cookies. Provider-verified factor and authentication time (`ActorContext.Assurance`, `AuthenticatedAt`). **Every** permission requires a multi-factor session (`Permissions.Add` sets `RequiresMfa: true`). Approvals and money-moving permissions also require authentication within 5 minutes (`AssurancePolicy`). Pinned by `ApprovedRuleConformanceTests.Every_permission_requires_multi_factor_and_privileged_decisions_require_fresh_authentication`. Login and step-up are limited to 20 per 5 minutes per IP. | L2 consideration: fresh authentication also for `TechnicalConfigure` and `AccessPropose`. |
| V7 Session management | Pass | An opaque server-side session token in `__Host-ut_session` (HttpOnly, Secure, SameSite=Lax), with absolute expiry. Live-session check on every request (`SessionPersistence.LiveFilter`). Revocation on logout and on suspension. Stale-session denials fail requests (`WorkSummaryService.IsSessionDenial`). | — |
| V8 Authorization | Pass | Deny-by-default scope policy per request (`ScopePolicy.Compile`/`Authorize`). Filtering happens before pagination and counts. Maker/checker with independent person evidence. Delegation is time-bounded. D02 conformance tests pin a Super Admin without business permissions (`ApprovedRuleConformanceTests`). | — |
| V9 Self-contained tokens | N/A | No self-contained tokens are issued to browsers. The session is opaque and server-side. | — |
| V10 OAuth/OIDC | Pass (provider-dependent) | Authorization-code flow through the platform OIDC handler, with correlation and nonce cookies. The issuer is approved by configuration. | Tenant configuration (allowed callback URLs, MFA policy) is D07. |
| V11 Cryptography | Pass | Provenance seals are HMAC with a key ring and key IDs (`ProvenanceSeal`, `SealKeyRing`). SHA-256 body hashes for idempotency. No custom cryptographic primitives. | Key custody and rotation runbook at hosting (D07). |
| V12 Secure communication | Pass (edge) | HTTPS-only `__Host-` cookies. HSTS in production. The API rewrite requires an HTTPS origin without credentials (`next.config.ts`). | TLS termination configuration at hosting (D07). |
| V13 Configuration | Pass | Configuration is validated at startup (Mongo URI and database names, the HTTPS API origin, the identity origin). Development-only OpenAPI. Forwarded headers are trusted only from configured proxies. The CI `supply-chain` job scans for committed secrets, vulnerable NuGet packages and high/critical npm advisories. | After the upgrade on 20 October 2026 the production audit reports no advisories; the remaining dev-only finding is recorded below. |
| V14 Data protection | Pass | `no-store` on private reads. Minimal data in audit/outbox and in WhatsApp text (`whatsappLink` refuses amounts and IDs). Purge after 30 days for discarded drafts, keeping audit (D2). Logs carry bounded statuses only. | — |
| V15 Secure coding and architecture | Pass | Per-domain modules. Owner-only writes. Integrity seals with fail-closed verification. Idempotent commands with original-receipt recovery. | — |
| V16 Logging and error handling | Pass | Audit events per command (append-only; purge never deletes audit). Workers log bounded status codes without content (`*Worker.cs`). Problem+json errors. | Operator health page `/operations/health` (counts, ages and states only; [commit 8927103](https://github.com/natannielz/Capstone/commit/8927103)). Named responder and alert routing at hosting (D07). |
