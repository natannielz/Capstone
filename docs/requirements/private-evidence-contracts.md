# Private evidence foundation contracts

Status: reviewed technical design for PAY01 implementation, 28 September 2026. These contracts guide the next implementation; they do not establish completed functionality or production acceptance. Start after the accepted accounting foundation and allocate the next migration after v12. The full [PAY01 plan](../superpowers/plans/2026-09-28-report-payments-ocr.md) and [report requirements](unit-toko-report-2026-09-28.md) remain binding.

## Identity and ownership

All domain IDs/versions/revisions below are positive BSON Int64; HTTP projects them through LongId/canonical decimal strings. Hashes are exactly 64 lowercase hexadecimal characters representing server-computed SHA-256. Null, default, noncanonical or out-of-range values reject before persistence.

| Proposed Modules contract | Exact meaning/invariant |
| --- | --- |
| `EvidenceRef(long Id, long Version, string Sha256)` | Id is the lineage ID, not the version-row primary key. Version identifies immutable original bytes in that lineage; hash covers those original bytes. Persist as `lineageId` + `contentVersion` with a unique compound index. Never repoint, overwrite, renumber or reuse a version. |
| `EvidenceVersionRow(long RowId, long LineageId, long ContentVersion, ...)` | Each version row has its own independently allocated positive Int64 Mongo `_id = RowId`; never set `_id` to LineageId for every version. EvidenceRef resolves through unique `(lineageId, contentVersion)` and exact hash. Lineage ownership/purpose stay fixed. RowId, LineageId and lifecycle revision are distinct identities. |
| `EvidenceTargetRef(EvidenceTargetKind Kind, long Id)` | Stable owning aggregate identity. First supported kinds: CatalogFamily and CatalogSku. A SKU target never follows predecessor/replacement links or moves to another family implicitly. No client-owned ResourceScope or object key. |
| `EvidencePurpose` | Existing planned purposes plus CatalogImage. First runtime slice registers only CatalogImage for the two supported target kinds; every other pair returns `evidence_target_unsupported`. Registration is explicit, not a generic collection lookup. |
| `EvidenceAssociationRef(EvidenceAssociationKind Kind, long Id, long Version)` | CatalogFamilyRevision uses family ID + the exact family revision; CatalogDefinition uses immutable definition ID + definition version. The immutable pin stores this tuple and the exact EvidenceRef. It is not a pointer to currentDefinitionId or latest image. |
| `EvidenceLifecycle(long Revision, EvidenceState State)` | Revision starts at 1 and increases on actual lifecycle mutation; it is not EvidenceRef.Version. States: reserved, quarantined, validated, failed, deleting, deleted. Fences/lease renewals can have separate counters and must not create new content versions. |
| `UploadReservation(long Id, long LineageId, long VersionRowId, long ContentVersion, long Revision)` | Durable upload identity allocated before external I/O with independently allocated lineage/version-row IDs. Exact target, purpose, uploader, limits/policy version, original operation key, expiry and server-generated ticket are private. Hash is absent until full staging completes; neither content version nor lifecycle revision is a primary key. |
| `EvidenceMetadata` | EvidenceRef, stable target, purpose, uploader, detected MIME, length, dimensions/frame/page counts, object generation, lifecycle, scan/decoder provenance and timestamps. Storage address and full provenance remain internal. A safe HTTP projection exposes neither address nor authority tokens. |
| `EvidencePin` / `EvidenceReadLease` | Pin is a durable immutable association protected by lifecycle fencing. Read lease is a separate bounded, token-owned access interval for one exact original/derivative generation; it grants no business approval and cannot be transferred to another actor or target. |

Reserve a new lineage at content version 1 in the first slice. Same logical reservation retry returns that reservation after current authorization; changed semantic target/purpose/request under the same key conflicts. Replacement/version-advance APIs remain unsupported until they can allocate under the lineage's expected-version fence and preserve every earlier reference. A renamed retry is not a changed semantic request. Once bytes are known, the reservation cannot accept a different length/hash.


Reservation mutation is bound to its original authenticated uploader as well as current owning-target authority. Upload, completion and recovery must reject a different actor; no implicit handover follows shared CatalogManage permission. A future explicit audited transfer workflow is outside this first slice. Ordinary authorized staff metadata reads follow their separate target policy.

## Stable Catalog target versus association

| Operation | Required server proof |
| --- | --- |
| Reserve/upload for existing family | Load family/category and exact authoring owner; current CatalogManage and active hierarchy; fence loaded heads and authority. Family must already exist, but may have no images. |
| Reserve/upload for existing SKU | Load SKU/current definition/family/category, validate their relationships and immutable SKU identity; apply the same authoring authority. Do not require the next definition ID to exist before upload. |
| Pin to family revision | Caller has written/loaded that exact family revision in the same transaction; association ID equals target family ID. Preserve the association snapshot in the pin when later family revisions replace the current master. |
| Pin to definition | Caller has inserted/loaded the exact immutable definition in the same transaction; definition.skuId equals target SKU ID and its version matches the association. The catalog mutation, pin, audit and receipt commit together. |
| Retain images when authoring creates a new revision/definition | Recheck eligibility and create new pins for every retained image against the new exact family revision/definition in the same authoring transaction. Preserve old pins unchanged. Copying image IDs or retaining only previous-version pins is insufficient; one failed retained-image pin aborts the whole mutation. |
| Staff read before association | Only current CatalogManage on the actual owning target; uploader identity alone is insufficient. First slice returns status only while evidence is quarantined or failed. |
| Buyer original/derivative read | Requires a real association reached through the requested currently visible SKU/family/definition and current catalog entitlement/publication. No association or no registered delivery adapter means unavailable. Historical reads need their separate owning-document policy. |

Family-target assets attach only to family-revision slots and SKU-target assets only to definition slots in this slice. Sharing/copying across target kinds is unsupported; this avoids a permissive cross-family asset rule. Buyer family-image access must still be reached through a visible SKU whose family matches the pin.

## Same-session Platform composition

The following are proposed internal members of the single Platform/Documents EvidenceService and its narrow target adapter. `tx` is an active caller-owned `IClientSessionHandle`; these members never start another transaction or perform object I/O. Modules remains independent of Mongo. Inputs are validated even for trusted callers. Any returned proof/result is provisional until the caller transaction commits.

| Proposed signature (CancellationToken last throughout) | Required behavior |
| --- | --- |
| `IEvidenceTargetPolicy.WithAuthorizedAsync<T>(tx, actor, target, purpose, access, association?, callback)` | Catalog-owned adapter resolves actual graph and supplies an opaque server-loaded authority to the callback, then fences the graph, current grants/memberships/hierarchy/session and time-dependent authority before returning. Authority is valid only in this transaction attempt and cannot be constructed from HTTP. Access is Upload, Associate, StaffRead or BuyerRead. |
| `EvidenceService.ReserveAsync(tx, actor, target, purpose, expectedTargetRevision, commandMetadata)` | Authorize Upload, reserve bounded capacity/lease and private storage ticket, insert safe audit and command receipt atomically. No file write inside the transaction. Initial implementation supports an existing image-free family/SKU target. |
| `EvidenceService.CompleteUploadAsync(tx, actor, reservationId, expectedLifecycleRevision, stagedPublication, commandMetadata)` | Reauthorize Upload and exact reservation; accept only a verified immutable publication proof for its ticket, hash and complete length; CAS reserved→quarantined and enqueue validation/audit atomically. The publication proof is internal and session-independent storage evidence, never browser input. |
| `EvidenceService.PinEligibleAsync(tx, actor, reference, expectedTarget, purpose, association, commandMetadata)` | Authorize Associate; private LoadEligibleAsync checks exact reference, target, clean/complete verdict and immutable-object integrity evidence; touch lifecycle fence and insert unique immutable pin in the same transaction as the owning association. Deleting/deleted or unverified evidence rejects. No durable consumer uses an unpinned LoadEligible result. |
| `EvidenceService.AcquireReadLeaseAsync(tx, actor, reference, expectedTarget, purpose, association?, derivativeRef?, readMetadata)` | Authorize the actual read path and exact derivative→original→association chain; touch lifecycle and create a bounded provisional lease/audit. After commit it protects integrity preparation from cleanup, but grants no permission to emit bytes. Return an internal, request-bound descriptor only. |
| `EvidenceService.FinalizeReadLeaseAsync(tx, actor, leaseId, token, verifiedHandleProof, readMetadata)` | After external integrity verification, reload and reauthorize/fence the exact target, association, actor/session, publication and evidence lifecycle. Match the still-open immutable handle's reference/generation/hash to the unexpired provisional lease. CAS provisional→active and insert required read audit. Its known-success commit is the read-authorization linearization point immediately before any byte emission. |
| `EvidenceService.RenewReadLeaseAsync(tx, actor, leaseId, token)` / `ReleaseReadLeaseAsync(tx, leaseId, token)` | Renewal requires an active lease, reauthorizes/fences current access and never extends beyond the bounded request deadline. Release is idempotent token-owned cleanup without requiring an active user. Expired/stale tokens cannot extend leases. Stop the stream immediately on failed renewal and no later than lease expiry; close the handle before release. |

Use existing authorization/session fences. For buyer composition, extract a same-session core from CatalogVisibilityStore.ReadCurrentAsync or run the Documents operations inside its authorized callback; never call its transaction-owning wrapper from another unit of work. Keep authoring pins inside CatalogAuthoringService's existing command transaction.

**Abort-on-failure contract:** CompleteUploadAsync, PinEligibleAsync and every required audit insertion must explicitly abort the supplied active transaction before rethrowing any failure, even if the owner catches that exception. Use bounded cleanup independent of an already-cancelled request token; preserve the original exception and Mongo error labels (`throw;`), never replace them with an abort error. If abort cannot be confirmed, invalidate/dispose the supplied transaction context so it cannot later commit. Propagation alone is insufficient. Required negative test: owner attempts a business association write, pin/required audit fails, owner catches the exception, and commit is impossible with no association or partial evidence effects persisted.

**Read orchestration:** The existing EvidenceAccessService gains one top-level `OpenAsync(actor, readRequest)` operation, called outside any transaction. (1) Commit the provisional lease in a short transaction. (2) Open/verify the exact immutable handle outside Mongo and hold it without emitting bytes. (3) Reauthorize/fence/finalize that exact lease in a new short transaction immediately before returning the guarded stream. Do not put object I/O in either retry callback. A slow verification cannot preserve an old authority decision. Failed/unknown finalization emits no bytes; close the handle and safely release/reconcile the lease. A retry must obtain a new known-success current-authorization commit. Descriptors/proofs are internal, single-use and request-bound; HTTP accepts references/reservation IDs, never keys, paths, URLs or authority tokens.

## Private storage capabilities and recovery

Only IPrivateEvidenceStore and its adapters know physical addresses. Storage tickets/addresses are opaque internal values generated by the service and constrained to its private namespace; the HTTP API carries reservation IDs only. Cancellation or a lost response never proves an external write did not happen.

| Proposed IPrivateEvidenceStore operation | Result and guarantee |
| --- | --- |
| `StageAsync(StageTicket ticket, Stream source, EvidenceLimits limits)` | Count actual bytes, bound time/disk, compute SHA-256, and produce `StagedContent(ticket, length, hash)` only after complete durable staging. Detect interruption/limit failure. Stage ticket is reserved before I/O; retries use a tracked new attempt or inspect the same completed attempt, never append blindly. |
| `InspectStageAsync(StageTicket ticket)` | Absent, Incomplete, Complete(length,hash), or Unavailable. Complete requires durable completion evidence and verification of actual staged bytes. An incomplete stage cannot be published. |
| `PublishAsync(StagedContent content, OriginalTicket destination)` | Create-only immutable publish: Published, ExistingIdentical, Conflict, or Unknown. ExistingIdentical requires exact complete length/hash/generation, not existence. No replace/upsert option. Destination is already durably bound to the reservation. |
| `InspectOriginalAsync(OriginalTicket destination)` | Absent, Present(immutable generation, actual length, verified hash), or Unavailable. Local adapter verifies bytes; generic user-set object metadata is not a trusted checksum. Conflict/mismatch is explicit and ineligible. |
| `OpenVerifiedReadAsync(StoredOriginal original)` | Outside Mongo, verifies actual integrity and holds a bounded immutable handle plus internal proof of its exact reference/generation/hash. This preparation emits no HTTP bytes and grants no access by itself; FinalizeReadLeaseAsync must reauthorize afterward. Dispose closes the handle without deleting evidence. |
| `DeleteClaimedAsync(DeletionClaim claim)` | Requires an internal committed tombstone/token for the exact generation. Deleted, AlreadyAbsent, Conflict, or Unknown; never delete whatever happens to occupy an address now. Not exposed through ordinary upload/read capabilities. |
| `DeleteStageClaimedAsync(StageDeletionClaim claim)` | Separate cleanup of one tracked staged attempt, including incomplete stages; requires an authoritative cleanup claim, stopped upload handles and no unresolved publish. Never infer that lease expiry alone stopped a writer or made its publication impossible. Initial cleanup stays unavailable until this can be enforced. |

Unknown publish: retain reservation/ticket, inspect exact destination, accept matching complete generation or remain unresolved; do not allocate a replacement logical receipt or delete. Unknown Mongo completion: retain object, query the original authorized receipt/reservation, and retry the same logical completion. Unknown delete: keep deleting state and reconcile exact generation until completion is known. No generic orphan sweep may delete a generation potentially covered by an unresolved reservation/commit.

## State transition preconditions

| Transition | Preconditions and atomic Mongo effects |
| --- | --- |
| none→reserved | Supported target/purpose, actual current actor/owner proof, target revision, configured resource limits and available store, reserved quota, unique command identity; reservation/audit/receipt commit before I/O. |
| reserved→quarantined | Live reservation/attempt, current target authorization, complete stage and matching immutable publication, expected lifecycle revision; freeze EvidenceRef/MIME claim/provenance, enqueue exact-version validation, audit and complete receipt. Detected MIME remains subject to decoder agreement. |
| quarantined→validated | Registered scanner and bounded decoder both completed for the same immutable reference/generation; exact supported MIME, complete decode, dimensions/resource limits satisfied, scanner clean, current validation claim/token and no tombstone; persist provenance/verdict/audit atomically. |
| quarantined→failed | Definite security/content failure for the exact claimed generation; audit safe reason and preserve original. Scanner/decoder unavailable, timeout or uncertain result stays quarantined with explicit error/retry status, never clean. |
| validated→quarantined | Integrity/security revocation CAS with audit; conflicts with pins/access leases through lifecycle fence. Existing immutable references and prior decisions remain history, but no new eligible use/read lease succeeds. No automatic business reversal. |
| reserved/quarantined/failed/validated→deleting | Configured retention/cleanup decision permits it; no legal hold, retained pin, unresolved completion or active upload/validation/read lease; CAS lifecycle and commit tombstone/token/audit. New pins and leases conflict/reject. No configured policy means no deletion. |
| deleting→deleted | Exact-generation deletion/absence verified for the current tombstone token; persist completion/audit and retain metadata required by configured policy. Ambiguous deletion remains deleting; stale workers cannot finalize. |

Every transition compares expected lifecycle revision and increments it. Lease claims/renewals/finalization and pins touch the same lifecycle record so cleanup cannot race a read-only snapshot. Lease substates are provisional→active→released/expired; provisional leases permit no byte emission, and active streams stop by their committed deadline or failed renewal. Deleting is terminal for eligibility. Required audit failure explicitly aborts the supplied transaction under the contract above. Old pins survive retirement/new images; retained images receive additional pins for every new association revision.

Required read-race acceptance: pause integrity verification, revoke the actor/entitlement or change the image association/security eligibility, resume, and assert finalization rejects with zero emitted bytes. Also prove two content versions receive distinct positive Int64 row IDs under the unique lineage/version key, and a failed re-pin of a retained image cannot commit the new catalog revision. These are proposed tests, not executed evidence.

## Genuine choices to settle at implementation freeze

| Choice | Recommended safe default for the real first slice |
| --- | --- |
| Exact ID/version allocation for replacements | New lineages at version 1 only; reject replacement operations until a reviewed lineage CAS is implemented. Do not overload lifecycle revision as content version. |
| Storage evidence freshness across Mongo and object I/O | Require create-only immutable generations; acquire provisional protection, verify/hold the exact handle outside Mongo, then perform a short current-authorization/fence/finalization commit before bytes. Missing/mutable storage capability returns unavailable. There is no claimed distributed transaction. |
| Scanner/decoder and technical limits | Unavailable adapters by default; injected explicit test-only scanner outcomes with real local storage/Mongo/decoder for integration. Unconfigured limits deny reservation. Choose no production media quotas, decoder license/runtime or retention duration here. |
| First target/read reach | Staff CatalogFamily/CatalogSku upload/status first; keep buyer delivery unavailable until real immutable association and four-layer catalog integration exist. Never seed associations or accept synthetic success in normal runtime. |
| Pin release, shared assets and retention | No release/reuse/delete authorization API in the first slice. Keep pins and deletion disabled without the relevant explicit policy/adapter. Implement later without altering original references. |

The full PAY01 plan still owns independent review and real adversarial integration acceptance. This proposal does not freeze deferred payment, OCR, business retention, production privileges or immutable-storage operational acceptance.
