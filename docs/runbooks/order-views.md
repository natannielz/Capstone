# Filter pesanan pribadi

Halaman **Pesanan saya** (`/ordering/orders`) dapat menyaring konteks cabang/divisi yang masih diizinkan dan mengurutkan ID pesanan dari terbaru atau terlama. Pilihan awal tetap semua konteks yang diizinkan dan terbaru dahulu. Pergantian arah atau konteks menghapus kursor lama; paginasi menggunakan kursor eksklusif yang terikat pada pilihan tersebut.

Pemilik akun dapat menyimpan filter, memuatnya kembali, mengubah nama, dan menghapusnya setelah memeriksa konfirmasi. Filter tersimpan hanya milik akun itu. Tautan berbagi memuat pilihan konteks/urutan, tanpa identitas pemilik, isi pesanan, atau otoritas akses. Penerima tautan tetap dibatasi ke pesanan miliknya dan aksesnya yang berlaku. Konteks yang dicabut ditolak saat pemuatan, perubahan, pengulangan, maupun pemulihan.

Referensi permintaan asli disimpan secara terpisah untuk setiap akun dan kunci di penyimpanan browser. Isinya hanya identitas operasi; nama serta isi filter tidak disimpan dalam jurnal tersebut. Jika respons hilang, tutup/buka browser tetap mempertahankan **Periksa hasil filter**. Hasil belum ditemukan, penolakan akses, konflik, atau koneksi gagal tidak menghapus referensi dan tidak membuat permintaan pengganti. Perubahan referensi dari tab lain membatalkan konfirmasi lama sebelum tab itu dapat menulis lagi.

API berada di `/api/v1/ordering/order-views`. Query, riwayat, dan pemulihan memakai otorisasi pemilik akun saat ini. Perubahan menyertakan `If-Match`, `Idempotency-Key`, aktor yang diharapkan, dan CSRF. Versi pemilik, audit, dan receipt asli harus saling cocok; hasil terbaru tidak digunakan sebagai pengganti hasil kunci yang diminta. Perubahan filter tidak mengubah pesanan, stok, pembayaran, atau transaksi komersial.

Migrasi112 mengikuti prefix nyata1–111 dan menambahkan penyimpanan head/versi filter beserta indeks yang divalidasi lengkap. Tidak ada placeholder migrasi, perubahan receipt lama, atau pemberian izin otomatis. Pengujian migrasi dijalankan pada database uji terisolasi; catatan ini tidak menyatakan migrasi produksi sudah diterapkan.

Validasi kandidat terisolasi tersimpan di `tmp/u07-order-views-validation-candidate/acceptance-isolated112-3.json`: 16 kasus native unik lulus setelah perbaikan guard indeks dan pengulangan tepat 10 kasus terdampak; 15 kasus client, pemeriksaan tipe/lint, ekspor kontrak, dan build frontend lengkap lulus. Browser asli membuktikan tiga commit, tiga respons hilang, tiga restart proses browser, pemulihan kunci asli, pembatalan tanpa write, penolakan akun/cabang, batas akses penerima tautan, serta tampilan1440/360 tanpa overflow. Dua kegagalan awal driver tetap disimpan; perbaikan hanya locator dan penunggu respons POST asli, dengan batas30 detik dan6 menit child tetap.

Integrasi main112 lulus build backend baru tanpa warning/error; seluruh 1953 input backend cocok dengan kandidat teruji. Ekspor kontrak dan client yang dihasilkan identik dengan hasil kandidat. Build frontend lengkap8 (`htrCL9uFdc7LZsRmJO7ct`) serta browser utama1 lulus (1/1, 7,0223 menit) dengan seluruh hash sumber, 24 DLL, dan hasil build tetap. Build lengkap7 serta output/types pilot dipertahankan.
