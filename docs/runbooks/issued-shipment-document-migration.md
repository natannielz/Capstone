# Issued Surat Jalan upgrade

Migration 25 installs the private `issuedDocuments` owner for generated Surat Jalan copies. It leaves migrations 1–24, accepted dispatches, document numbering and uploaded evidence unchanged. Existing dispatches can be explicitly issued after the upgrade; the migration creates no business documents.

1. Select the reviewed release and approved environment. Pause/drain application, worker and integration writers; the deployment lease does not stop business writes.
2. Verify a coordinated backup/restore set containing dispatch/order/reservation/movement history, numbering/ID counters, access/session records, audit, original command receipts, outbox and generated documents. Preserve uploaded private evidence under its separate storage runbook. A document restored without its accepted source and provenance is unavailable.
3. Inspect the new collection and reverse issuance effects. Preflight rejects unexpected existing document data, issuance audit/receipt/outbox effects, unsafe retention/uniqueness, invalid counters and incompatible storage before DDL. Preserve unexpected data for reviewed conversion; do not erase it or synthesize acceptance records.
4. Run the existing worker migration entry point from `backend`: `dotnet run --project src/UnitToko.Worker -- --migrate`. Verify version 25 and unchanged predecessor receipts. Stronger compatible validators and safe counters survive; an interrupted compatible empty installation can resume after the old deployer stops and its lease is released or legitimately expires. Keep writers paused during recovery.
5. In isolated approved staging, use a dispatched partial shipment. A staff account needs explicit scoped `shipment.prepare` to issue. The current shipment screen additionally requires `shipment.read`; role templates are not widened. Review the fixed destination and dispatched packages, issue once, lose the response and recover the original receipt. Confirm one document/audit/receipt/outbox and no additional stock or monetary effects.
6. Check assigned-courier, own-buyer and scoped staff downloads, along with unrelated-account denial and membership/session revocation. Compare exact UTF-8 byte length and SHA-256 across repeated downloads. Corrupt/missing source, document, audit or receipt must fail closed, including attempts under a new request key.

The canonical representation is bounded printable HTML (maximum 512 KiB), encoded from accepted server-owned snapshots and stored as fixed private Mongo content. It has no scripts, remote resources or client-supplied markup. Browser downloads verify its hash and remain authenticated POST requests with current account, scope, CSRF and session checks; no public object URL is issued. Read uses the stored bytes, not a newer renderer. Uploads/signature/payment images remain in the existing private evidence architecture. A later format or correction must be a linked immutable version under a reviewed forward change, never an overwrite.

The number belongs to the accepted dispatch and is not allocated again during document issuance. A Surat Jalan records dispatch, not recipient acceptance, an invoice or certified electronic signature. Recipient-bound QR/tablet proof, discrepancies/returns, broader document search, invoice eligibility/notifications, live provider acceptance and migration/restore/pilot remain M2–M6 work. No external message, live migration or cutover is authorized by this runbook.
